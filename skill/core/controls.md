# 14 个润色控件

每个控件 = **一个对文本的操作** + **一个可测指标** + **一条失败案例**。
`D` = 引擎里可用 `apply --controls` 直接执行的确定性控件；`L` = 需要模型判断（引擎只提供指标）。

| id | 名称 | 类型 | 操作 | 可测指标 | 通过条件 |
|---|---|---|---|---|---|
| `cf` | 拆分长句 | D | 中文 `——` 换成句号/冒号；> 45 字的句子在「，+ 关联词」处断开 | 破折号计数、平均句长 | 破折号 0；平均句长 ≤ 45 |
| `ai` | 清除 AI 词 | D | 替换 赋能/闭环/抓手/底层逻辑/体系化/显著提升… | 词表命中数、每千字 AI 词量 | ≤ 2/千字 |
| `num` | 打散编号腔 | D | 删掉「首先，/其次，/最后，」，改用时间或因果过渡 | 编号词每千字 | ≤ 1/千字 |
| `fil` | 删冗余状语 | D | 深入地/切实地/有效地/全面地…直接删 | 状语密度 | 0 |
| `hed` | 去对冲话术 | D | 一定程度上/可以说/相对而言 删或替换为具体条件 | 对冲词计数 | 0 |
| `unv` | 绝对化改有条件 | D | 一定/必然/绝对/从不/证明 → 「在…条件下」「目前观察到」「支持」 | 绝对化每千字 | ≤ 2/千字 |
| `mon` | 降低术语密度 | L | 术语**首次**出现处插入一句解释（`X 是指…`），不替换术语 | 术语每千字、首次解释率 | 术语每千字 ≤ 40 或解释率 100% |
| `met` | 加可核验细节 | L | 抽象判断 → 数字/日期/专名，但**只能加能查到来源的** | 数字/专名增量、来源链接数 | 每个新增数字都有来源 |
| `ana` | 加类比（附失效边界） | L | 只在中立场景给类比，且必须同时给「它在哪里不成立」 | 类比数 / 边界句数 | 两数必须相等 |
| `sub` | 恢复主语 | L | 找出被省略的动作主体；把「通过…可以得到」改成「我们/实验者…得到」 | 无主句计数 | 0 |

## 为什么是这 14 个

它们覆盖中文 AI 腔与学术腔的**不同成因**，不是同义替换：

- `cf` / `num` / `fil` / `hed` —— 句子层面的机械感
- `ai` —— 词汇层面的空转
- `unv` / `sub` —— 逻辑层面的责任转移（谁在断言、有什么条件）
- `mon` / `met` / `ana` —— 知识层面的可理解性与可核验性

## 失败案例（来自真实样本 `简报思路(3).docx`）

1. **`cf` 只改一处就够** —— 白洞段 tell 38.3，改掉「更绝望的是」+破折号 → 0.0。
   不要整段重写：重写会引入新事实漂移。
2. **`unv` 不能全局替换** ——「100亿年」前面不能加「在实验范围内」，
   那是物理量不是判断句。`unv` 只作用于**断言动词**，不作用于数量词。
3. **`ana` 的边界句不是免责声明** —— 正确写法：「白洞像反向播放的黑洞；
   但这个类比在 '白洞的形成机制' 上不成立，因为反向方程不保证有物理解。」
   错误写法：「以上只是类比，仅供参考。」
4. **`met` 的高危操作** —— 给「很多研究」补「37 项研究」听起来更严谨，但如果数字是编的，
   严谨化就变成了伪造。**只能补有链接的数**，补不到就写「尚无确切统计」。

## 控件组合顺序（不要乱序）

```
unv → mon → sub → cf → ai → num → fil → hed → met → ana
```

先修事实层（unv/mon/sub），再修句法层（cf/ai/num/fil/hed），最后才是修辞层（met/ana）。
理由：先加类比后改条件，类比会跟着错的条件一起被固化。
