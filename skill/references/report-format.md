# 批注本（report.html）格式契约

用户明确要求过的形态：**文本放进来 → 在输入这一步就选「严谨化」或「通俗化」→ 直接得到一份报告**。
不是「先给两份，再让读者切换」。所以这个文件只有一条主路径：

```
封面（摆出原文 + 两个改法按钮）
      ↓ 点其中一个
报告（只渲染选中的那一份，页头有「换一种改法」可退回封面）
```

**一份稿件只讲一种改法。** 两种改法的批注、改写、事实核对是各自独立的，
不要为了「省一次渲染」把它们塞进同一个视图做对比——实测这样读者会以为是同一份稿子的两个视图。

---

## 文件骨架

`templates/report.html` 是一份可以直接跑的完整实现。新文本只需换三个载荷，
CSS 与交互层不动：

| 载荷 | 形状 | 说明 |
|---|---|---|
| `SRC` | `{chars, excerpt, paras}` | 原文元信息。`excerpt` 是封面引用的首句 |
| `ORIG` | `{rig:[html...], pop:[html...]}` | 逐段原文；问题片段用 `<mark data-n="N">…</mark>` 包住 |
| `DATA` | `{rig:{...}, pop:{...}}` | 两份报告正文。缺哪个改法就只写一个键 |

`ORIG` 两个改法放同一份原文（同一段文字、同一批 `<mark>`）——批注不同，原文相同。

---

## `DATA[key]` 字段

没有的字段就不写，页面上那一整块不出现。

| 字段 | 类型 | 说明 |
|---|---|---|
| `key` / `label` | `'rig'`/`'pop'`、`'严谨化'`/`'通俗化'` | 键名必须与 `DATA` 的键一致 |
| `title` | HTML 串 | 报告标题。允许 `<em>` 上朱红，全角冒号用 `<span class="c">：</span>` 收边 |
| `byline` | `string[4–5]` | 形如 `['原文 1,445 字','10 段','10 处批注','改写 721 字','断言强度 27.1 → 0.0']` |
| `hint` | 一行 | 顶栏那一句「这份报告只做一件事…」 |
| `verdict` | `string[]`（2 段） | 整体点评。第一段说病症，第二段说这份稿子怎么处理 |
| `stats` | `[{lab, before, after, note, dir}]` | 4 个指标。`dir` 取 `good`/`flat` |
| `annots` | `[{i, notes:[{n, tag, text}]}]` | `i` 是段号（从 1 起）；`n` 是页边注编号（从 1 起、全文连续、与 `<mark data-n>` 对应）；`tag` 是四字以内的病名 |
| `rewrite` | `[{paras:[string], why:[string]}]` | `paras` 是这一段改写后的正文（纯文本，会被 `esc`）；`why` 是右栏那几条「为什么这样写」 |
| `summary` | `string[]`（3–5 条） | 内容总结。最后一条指向写作意图 |
| `facts` | `[{claim, verdict, kind, basis}]` | 仅 rig。`kind` 取 `bad`/`mid`/`ok`，`verdict` 是二字判词 |
| `advice` | `[{t, body, how}]` | 学习建议。`t` 是一条判断，`body` 是解释，`how` 是「怎么查」的动作 |
| `colophon` | 一行 | 页脚左侧；右侧固定写「双镜片批注本 · 1 份原文 / 2 种改法」 |

**编号规则**

- `annots[].i` 必须与 `ORIG[key]` 的下标对齐（`i = 下标 + 1`）。
- 没有问题的段落也要在 `annots` 里占位（`notes: []`）——页边注位会显示「这一段没有问题」，
  这让「哪些地方干净」也成为信息。漏掉则不显示。
- `notes[].n` 全文连续递增；`<mark data-n="N">` 的 N 与它一一对应。数量对不上读者就配不上号。

## 排版规则（不是审美偏好，是这份文档的骨架）

- **正文宋体、界面无衬线。** 正文字号 17px / 行高 2.0；页边注 12.5px / 1.72。
  两者用不同的字族，读者一眼就知道哪是文章、哪是批注。
- **批注靠 grid 对齐，不靠 JS 定位。** 每段是一行 `grid`：
  `grid-template-columns: minmax(0,1fr) 254px`，`gap: 44px`。
  正文进第一列，页边注进第二列，同一行的注自然贴着同一段。
- **`<mark>` 必须补上标编号。** 灰 `#6B635C` + 粗细 700 + 斜体 + 砖红点线底边；
  后面接 `<sup class="n">N</sup>`。没有上标，读者无法把正文和页边注配对。
- **一个强调色。** 朱红 `--vermilion:#B23A2E`，只用于：标题里的那一小段、编号、判定词、上标。
  其余全走墨色与灰阶。
- **分节用分隔线，不用卡片。** `.sec{padding:48px 0 8px; border-top:1px solid var(--line)}`。
- **节号动态发。** 缺块不留空号（rig 有事实核对 → `00–04`；pop 没有 → `00–03`）。
- **对比度全部过 WCAG AA。** 灰字 `--muted:#6B635C` 在 `#FBFAF7` 上是 4.9:1；
  不要为了「淡一点」把它降到 3:1 以下。
- **窄屏不许藏结论列。** ≤520px 时事实表改成一条一叠（原文 / 判词 / 依据三行），
  绝不能 `display:none` 掉判定列——那是整张表唯一有结论的一列。
- `prefers-reduced-motion` 与 `@media print` 都要处理（打印时隐藏按钮，`break-inside:avoid`）。

## 生成一份新报告的顺序

1. 把文本存进 `tmp/input.txt`（纯文本）。
2. `python3 core/zh_sci_lens.py analyze tmp/input.txt --mode auto --json` → 定模式、拿基线数字。
3. 逐段读，记下：哪一句太长、哪个断言没来源、哪个数字可核验、哪个段落干净。
4. 只对第 3 步挑出来的东西搜网核证（不要泛搜）。
5. 写 `ORIG`：逐段原文，问题片段用 `<mark data-n="N">` 包住。
6. 写 `DATA`：先写 `verdict`（结论先行），再写 `annots`（编号与 mark 对齐），
   再写 `rewrite`（改写 + 为什么），最后 `summary` / `facts` / `advice`。
7. 复查三条：**mark 数 = note 数**、**byline 里的批注数与实际一致**、
   **正文里出现的每个数字都能在 analyze 输出或核对表里找到出处**。
8. 浏览器打开，检查：封面两个按钮都能进报告、「换一种改法」能退回、零 JS 报错、窄屏不溢出。

> 第 5–6 步的判断全部由模型写。引擎只负责测「改前改后差多少」，
> 它写不出「为什么这句要改」——那正是这份报告的价值所在。
